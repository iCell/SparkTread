# Asset Design Brief — 交给外部设计 Agent / 美术师

Status: 待外部设计稿  
Authority: `PRODUCT_IMPLEMENTATION_PLAN.md` · `ASSET_PRODUCTION_MANIFEST.md` · ADR-0001/0004  
本文件的作用：让外部产出的设计稿能够直接落进工程。风格由你决定，但下列**硬约束**由引擎和产品决定，换风格也必须满足。

---

## 1. 不可违反的硬约束

这些不是美术偏好，违反了就无法进游戏。

### 1.1 严格正俯视（top-down orthographic）

- 无地平线、无等距（isometric）、无三四分之一视角、无透视变形。
- 坦克可以有浅浮雕高光和短接地阴影，但**足迹与朝向必须无歧义**。

### 1.2 旋转精灵禁止方向性主光 ★最容易踩

- 坦克底盘、炮塔、附件、投射物、地雷**在运行时按 90° 增量旋转**，只提供一张朝上（UP）的母版。
- 因此这些素材**不能烘焙左上主光**——否则朝右时光就从右上来了，与地形不一致。
- 允许：以支点为中心的径向/环境光、描边边缘对比、自发光条。
- 地形、基地、UI、Key Art **不旋转**，可以也应该使用统一的左上主光。

### 1.3 全屏可读性门槛（ADR-0004）

- 最低支持设备：390×844 点级别。整张 48×27 竞技场始终全部可见。
- **一辆标准坦克在屏幕上只有约 29×29 点**。所有造型必须在这个尺寸下成立。
- 灰度下仍需可区分：颜色不能是唯一信息通道。
- 触摸目标 ≥ 44×44 点。

### 1.4 模块化组合，不是逐个绘制

24 个敌人原型**必须**由模块拼装，不能是 24 张互不相关的画：

```
底盘(4) × 炮塔(6) + 装甲覆盖层(4) + 火力覆盖层(4) + 装备附件(4) + 危险标记(3) + 受损覆盖层(3)
```

图层顺序（自下而上）：
```
接地阴影 → 履带(2帧循环) → 底盘 → 装甲覆盖层 → 装备附件
→ 炮塔+炮管 → 火力自发光条 → 危险标记 → 环境光 → 受损覆盖层 → 玩家身份环
```

### 1.5 武器身份靠轮廓，不靠颜色

六个武器家族必须在**纯灰度、29 点**下可区分。当前设计约定（可改，但必须保持这种级别的差异）：

| 家族 | 轮廓特征 |
|---|---|
| normal | 单根中等炮管 |
| rapid | 双细管 + 尾部弹鼓 |
| fire | 短粗管 + 喇叭喷口 + 燃料罐 |
| ap | 最长最细 + 双制退环 |
| explosion | 短粗臼炮 + 宽炮口环 |
| mine | **无前向炮管**——顶部料斗 + 尾部布雷槽 |

## 2. 技术规格

| 项目 | 值 |
|---|---|
| 一个地形格母版 | 128 × 128 px |
| 一辆标准坦克母版 | 256 × 256 px 透明画布（= 2×2 格） |
| 支点 | 画布正中心 (128, 128)，必须精确 |
| 朝向 | 唯一一张朝上（UP）母版 |
| 世界尺寸 | 1 格 = 1024 子单位；坦克 = 2048 子单位（ADR-0001） |
| 导出 | 无损 PNG + alpha，sRGB；矢量源保留分层 |
| 履带动画 | 2 或 4 帧循环 |
| 命名 | 全小写 snake_case，见第 4 节 ID 清单 |

四个底盘的相对宽度（当前基准，可调但需保持递进关系）：scout 196 / standard 212 / armored 224 / heavy 236（相对 256 画布）。

## 4. 稳定 ID（不可自由改名）

素材文件名必须与内容 ID 一致，否则内容校验器会报错。

```
武器家族: normal rapid fire ap explosion mine
装备:     amphi_tank anti_skid shield_of_moon memory_of_sea
底盘:     scout standard armored heavy
主题:     frontier floodplain frozen_works iron_citadel
敌人原型: normal_a..d rapid_a..d fire_a..d ap_a..d explosion_a..d mine_a..d
道具:     见 ASSET_PRODUCTION_MANIFEST.md 4F（00..24，含 freeze_enemy / ammo_crate 等确定拼写）
```

24 个原型到底盘/覆盖层/装备的映射是**数据决定的**，不由美术自由发挥：见 `Assets/Design/Tanks/archetype_map.csv`。底盘按装甲值分配（1=scout, 2=standard, 3–4=armored, 5–6=heavy），自发光条数量 = 火力等级。

## 5. 明确禁止

- 复制或描摹《决战坦克》原版精灵、地图贴图、标题、Logo、音乐、音效；
- 真实国家/军队徽记、现实军车型号、商标；
- 坦克拟人脸、眼睛、毛绒感、学龄前造型；
- 任何会造成裁剪/滚屏/拉伸需求的构图；
- 只靠颜色区分的敌人变体或地雷等级。

## 6. 来源与权利（必须随稿提交）

每一件素材需要一条记录，缺失即无法进入发布版：

```
asset_id / creator_or_generator / generator_tool_and_version / generator_terms_snapshot
generation_prompt_or_brief / source_files / license_or_contract / license_evidence_path
creation_date / modifications / required_attribution / approved_platforms
content_hash / review_status / approved_for_shipping
```

若使用生成式工具，必须记录**工具、版本与当时的服务条款快照**——不同工具对产出物的商用授权差异很大。

## 7. 验收门槛

设计稿要通过才算完成：

- [ ] 灰度对照通过：六个武器家族仍可区分；
- [ ] 色觉障碍对照通过；
- [ ] 真机 29 点尺寸可读性通过（390 点级别设备）；
- [ ] 旋转测试：同一母版旋转 0/90/180/270 后光照方向不变；
- [ ] 支点与 bounds 校准正确；
- [ ] 模块可组合出全部 24 个原型且不穿帮；
- [ ] 命名与 ID 清单一致；
- [ ] 来源台账完整。

## 8. 当前仓库内的占位素材

`Assets/Design/` 下现有 206 个 SVG 是**参数化生成的占位/规格参考**，用途仅限：

1. 证明模块系统与图层顺序可行；
2. 提供精确的比例、支点、尺寸和 24 原型映射；
3. 让引擎在拿到正式美术前可以跑通渲染与可读性测试。

它们**不是设计方向的参考**，外部设计不必沿用其造型语言。已知不足（供设计方避免）：轮廓由几何基元堆叠而成而非造型设计、明度结构过窄、配色发闷、细节密度均匀缺乏主次、特效为同心圆叠透明度。

正式设计稿到位后，这批文件应整体替换。
